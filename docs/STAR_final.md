# Qoder码力星期四·小鹏 AI 出行Agent —— 双模式出行服务编排管家

> 论坛发帖标题请原样以本行标题开头。

## S · Situation 场景与痛点

智能座舱与 Robotaxi 已具备空调、导航、订单、改点等基础能力，但用户一句自然语言背后往往是风险与目标的组合：

- 车主说“有点困，放首歌” → 真实风险是疲劳驾驶，娱乐不能当主策略
- Robotaxi 乘客说“我跑到马路对面去上车” → 真实风险是穿行事故，应改安全落客区
- 后排宝宝喊热要求开窗 → 需要儿童锁与温控，而不是简单开窗
- 乘客头晕求助 → 必须舒适辅助 + 安全停车 + 转人工

痛点：若 Agent 只做指令映射或普通聊天，会错过安全边界与服务闭环。

## T · Task 任务与成功标准

打造更高层的 **AI 出行服务编排 Agent**，在已有工具之上完成：

1. 识别车主自驾 / Robotaxi 乘客真实意图与风险等级  
2. 组合工具形成可解释服务计划（调用顺序清晰）  
3. 对高风险动作拒绝、降级或转人工  
4. 通过 Web Demo（含公网链接）让评委一键复现至少 4 类典型场景  

成功标准：输出同时包含「自然语言回复 + 结构化服务计划 + 工具调用理由 + 禁止动作 + 安全提示」。

## A · Action 方案与实现

- **架构：** FastAPI + 多轮编排引擎（意图理解 → 安全评估 → 工具执行 → 结果回灌 → 收敛回复）
- **模型：** 阿里云百炼通义千问负责意图与工具规划；规则引擎做安全护栏；无 Key 时自动降级
- **工具箱：** 座舱（空调/座椅/媒体/疲劳辅助）、导航/休息点/超充、Robotaxi 订单/定位/改点/改目的地/舒适辅助/转人工
- **安全规则：** 疲劳禁娱乐主策略、禁止引导横穿、儿童强制锁门、求助强制转人工、施工/危险临停强制改点
- **体验：** 深色座舱 HUD + Robotaxi 会合示意 + 工具时间线 + 世界状态前后对比 +「评委一键剧本」
- **部署：** Docker 单容器托管于阿里云轻量应用服务器；可选 OSS 托管静态资源

## R · Result 结果与价值

- 覆盖赛题推荐的 8 类标准场景，评委剧本固化 4 个高风险闭环（2 车主 + 2 Robotaxi）
- 本地一键启动与公网可访问入口（见部署文档）
- 自动化测试覆盖场景理解、工具闭环、安全拦截与转人工
- 可扩展到真实座舱 SDK / Robotaxi 订单 API，而不改变编排层协议
